## But the starter still does not build

The build gets past CSS and dies in type checking instead:

```
./app/api/copilotkit/route.ts:13:5
Type error: Type 'HttpAgent' is not assignable to type 'AbstractAgent'.
  Types of property 'messages' are incompatible.
    ...
    Property 'activityType' is missing in type '{ role: "reasoning"; ... }'
      but required in type '{ id: string; role: "activity"; ... }'.

  13 |     weather_agent: agent,
     |     ^
Next.js build worker exited with code: 1
```

Cause: **three different `@ag-ui/client` versions in one tree**, from the
starter's own committed lockfile — not from anything this re-test did.

| Path | `@ag-ui/client` |
| --- | --- |
| `node_modules/@ag-ui/client` | 0.0.45 |
| `@copilotkit/react-core/node_modules/@ag-ui/client` | 0.0.43 |
| `@copilotkit/runtime/node_modules/@ag-ui/client` | 0.0.43 |
| `@copilotkitnext/*/node_modules/@ag-ui/client` | 0.0.42 |

`HttpAgent` comes from 0.0.45; the `AbstractAgent` that `CopilotRuntime` expects
comes from 0.0.43. Structurally different types, so the assignment fails.

This is the same defect as **Known issues #4** in the root README, which was
found independently against the doc pages — there it surfaces as a private
`_debug` field rather than `messages`, because the version pair differs. Same
root cause, two surfaces, found two ways.

`package.json` asks for `"latest"` on all five CopilotKit and AG-UI packages, so
what any given user gets depends on the day they run `init`.

## And the starter's Python backend cannot import itself

`agent-py/backend.py` opens with the exact lines every AG2 doc page uses:

```python
from autogen import ConversableAgent, LLMConfig
from autogen.ag_ui import AGUIStream
```

Its `requirements.txt` asks for `ag2[openai,ag-ui]`. Installing precisely that:

```
$ uv pip install "ag2[openai,ag-ui]"      # resolves ag2 1.0.3
$ python -c "from autogen import ConversableAgent, LLMConfig"
ModuleNotFoundError: No module named 'autogen'
```

**The starter ships a backend that its own requirements file cannot run.** This
is `backend/API_DRIFT.md` §1 — the docs' headline finding — reproduced in the
official scaffold. The 1.0 release renamed the top-level package `autogen` →
`ag2`; the `ag_ui` module moved with it, the agent API did not survive, and
neither the docs nor the starter were updated.

## Also worth noting

**The starter and the docs teach different APIs.** The lockfile pins CopilotKit
at **1.51.4** while `npm dist-tag` says `latest` is **1.69.3** — eighteen minors
back. 1.51.4 is the v1 surface: `app/page.tsx` imports `CopilotChat` from
`@copilotkit/react-ui` and `useCopilotAction` from `@copilotkit/react-core`,
and `route.ts` uses `copilotRuntimeNextJSAppRouterEndpoint` with
`ExperimentalEmptyAdapter`. Every AG2 doc page is written against the v2
surface — `@copilotkit/react-core/v2`, `createCopilotRuntimeHandler`,
`useAgent`, `useRenderTool`. Finish the quickstart via the CLI and none of the
subsequent doc pages match the app you are holding.

**`ag2` is the only framework `copilotkit framework list` marks with no
supported flags** — no `-i` (Intelligence threads), no `--mock`, no `--channel`
— where every other Python framework supports at least `-i`.

**`init` reported success on a failed install.** It printed
`🪁🤝🤖 App "ag2app" created successfully!` and then, on the next line,
`Install didn't finish after a retry.`
