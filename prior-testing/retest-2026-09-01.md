# Re-test of the blocked run — 2026-09-01

`report.md` was blocked at *Basics → Prebuilt Components* by a Tailwind error,
leaving 15 sections untested. This file re-runs that.

**The report was right.** An earlier draft of this file said the Tailwind
blocker "no longer reproduces" — that was wrong, and the mistake is worth
recording: it tested the wrong artifact. `report.md` used `ag2-samples`, the
repo the **Quickstart** page tells you to clone. The first re-test used
`npx copilotkit@latest init -f ag2`, which scaffolds a different app entirely.
Two different apps, two different failures, and only one of them was the one
being reported.

---

## The finding

`ag2-samples/ui` is a **Tailwind v3** project. The stylesheet the **Prebuilt
Components** page tells you to import ships **pre-compiled by Tailwind v4**.
Following both documented steps puts them in the same build, and it stops.

```
git clone https://github.com/ag2ai/ag2-samples.git   # Quickstart, step 2
cd ag2-samples/ui && pnpm install                    # resolves its pinned 1.67.1
```

Then the Prebuilt Components page's Setup step, verbatim, into `app/layout.tsx`:

```tsx
import "@copilotkit/react-core/v2/styles.css";
```

`npx next build`:

```
Failed to compile.

./node_modules/…/@copilotkit/react-core/dist/v2/index.css
Syntax error: …\@copilotkit\react-core\dist\v2\index.css `@layer base` is used
but no matching `@tailwind base` directive is present.

  1 | /*! tailwindcss v4.1.18 | MIT License | https://tailwindcss.com */
> 2 | @layer properties{@supports (((-webkit-hyphens:none)) and …
```

`next dev` fails the same way and serves a 500 with Next's Build Error overlay
on every route — which is what `image.png` in this directory shows.

**Nothing is upgraded and nothing is misconfigured.** These are the sample's own
committed pins:

| | |
|---|---|
| `tailwindcss` (the project) | `^3.4.1` → 3.4.19 |
| `@copilotkit/react-core` | `1.67.1` |
| `dist/v2/index.css` inside it | built with **tailwindcss v4.1.18** |
| `next` | 15.5.23 |

Tailwind v4 emits `@layer properties` and `@layer base`. Tailwind v3's PostCSS
plugin sees a bare `@layer` with no matching `@tailwind` directive and stops.

**Severity: blocking.** Prebuilt Components is the first page after the
Quickstart, so every section after it is unreachable — exactly what `report.md`
recorded.

**Not reproducible without the Setup step.** At the pinned versions, before
adding that import, `ag2-samples/ui` builds and the chat renders. The v1
stylesheet it ships with (`@copilotkit/react-ui/styles.css`) is fine. The
defect is the pairing of the two pages, not either one alone.

### One inconsistency in the original report

`report.md`'s Tested Context lists `@copilotkit/*` at **1.69.2**, but
`ag2-samples/ui` pins **1.67.1** and nothing in the repo resolves to 1.69. The
error does not need 1.69 — it reproduces at the pinned 1.67.1. The version table
looks like it was filled in from somewhere else; the finding itself stands.

## A second, unrelated failure: the CLI starter

Found while testing the wrong artifact, and worth keeping — it is a real defect
on a different path.

`npx copilotkit@latest init -f ag2` produces an app that does not build either,
for an unrelated reason. Its own committed lockfile carries **three**
`@ag-ui/client` versions:

| Path | Version |
| --- | --- |
| `node_modules/@ag-ui/client` | 0.0.45 |
| `@copilotkit/react-core` / `@copilotkit/runtime` | 0.0.43 |
| `@copilotkitnext/*` | 0.0.42 |

`HttpAgent` comes from one, the `AbstractAgent` that `CopilotRuntime` accepts
from another, so `next build` fails with `Type 'HttpAgent' is not assignable to
type 'AbstractAgent'`. Same root cause as **Known issues #4** in the root
README, found independently against the doc pages.

Its Python half does not run either: `agent-py/backend.py` uses the docs'
`from autogen import ConversableAgent` lines, and its `requirements.txt`
resolves `ag2` 1.0.3, which has no `autogen` namespace — `API_DRIFT.md` §1,
reproduced in the official scaffold.

The starter also pins CopilotKit at **1.51.4** while `latest` is 1.69.3, and
1.51.4 is the v1 surface — so the starter and the AG2 docs teach different APIs.
Source under `cli-scaffold/`, output in its `BUILD-ERROR.log`.
